## 1. Feature Name & Executive Summary

**Feature Name:** Baseline Shift

**Summary:**  
This feature allows for the modeling of a code or standards upgrade or downgrade. This allows for more accurate representation of the savings claimed by a program. Two processes occur during a baseline shift year. 1. The Adoption model will stop accepting upgrades that go to the previous baseline(eff_level_0) as that is not legal the upgrades that would have gone to eff_level_0 now go to eff_level_1. 2. The savings generated when eff_level_1 gets installed becomes zero and when eff_level_2 installed it is eff_level_2 - eff_level_1 rather than eff_level_2 - eff_level_0. (shifting the baseline changes the delta savings and costs generated by the measure in each market) (Ret_er adjusted following ret_er pattern)
---

## 2. Business Justification / Problem Statement

### Current Problem
Currently there the model assumes that the baseline conditions is always where savings and costs are compared against.
This is not the case when codes and standards would make the program shift the baseline to a higher or lower efficiency level. (for now only lower
but the end year is used to drop it back down)


### Business Impact
- Adding this will make results more accurate
- User Impact - This will allow the Modeler the ability to apply codes and standards dynamically
- Addresses Stakeholder concerns of shifting baseline

### User Stories
- **As an** analyst, **I need to** [capability] to change the baseline and measure type, **so that** reality is better reflected


### Success Criteria
- The User is able to simply enter year values in the start_baseline_year and end_baseline_year rows of the workpaper for a particular condition and
the code creates the needed measures (will add a new measure for the baseline shift as eff_1 becomes baseline to the top 10)
- For now the adoption model during baseline_shift years there will be no adoption of the eff_level_one measure
- The retirements and savings generated are now against the higher efficient condition not the eff_level 0. Because we dont care what was retired we only care about what the program claims for savings
